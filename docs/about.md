# 关于本项目

## 项目目标

实现从 Markdown 文档到公开网站的自动化发布，把「写文档」和「发布网站」这两件事彻底分开。

## 技术组成

| 工具 | 作用 |
| --- | --- |
| Markdown | 编写文档内容 |
| MkDocs Material | 将文档构建成静态网站 |
| GitHub Actions | 自动执行安装、构建和部署 |
| GitHub Pages | 托管并提供网站访问地址 |

## 各部分的职责边界

理解这套方案的关键，是分清「源码」和「产物」：

- `docs/` 是**源码**，是我手写的内容，需要提交到仓库。
- `site/` 是**产物**，由 MkDocs 根据 `docs/` 和 `mkdocs.yml` 生成，属于一次性输出，已经写进 `.gitignore`。
- `.github/workflows/deploy.yml` 是**流水线定义**，描述构建和部署的步骤。
- GitHub Pages 是**托管平台**，只负责把产物发布到公网。

因为 `site/` 完全可以由源码重新生成，手工修改它毫无意义——下一次构建会把它整个覆盖掉。
这也是我把 `site/` 排除在版本控制之外的原因。

## 为什么选 MkDocs Material

我对比过几种静态站点方案，最终选它的理由有三个：

1. 输入就是纯 Markdown，不需要学模板语法。
2. Material 主题自带中文导航、搜索、深色模式，开箱即用。
3. 构建命令简单，`mkdocs build --strict` 还能把死链和配置错误当成错误处理，适合放进 CI。
